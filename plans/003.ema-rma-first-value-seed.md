# 003 — Plan: seed EMA/RMA from the filled window

## §1. Solution

Delete the running total from both `calculate()` bodies and read the
seed from the window itself, which by definition holds exactly the last
`interval` inputs once `isFilled` — including the one that filled it
(spec §3).

Both classes become:

```ts
if (!h.isFilled) return null                 // not enough inputs yet
if (isNaN(s[CURRENT])) {
  const seed = average(h.array)              // the simple average of the window
  if (isNaN(seed)) return null               // a gap inside the window: wait
  s[CURRENT] = seed
  return s[CURRENT]
}
// unchanged regular branch
```

`average()` is the library's existing arithmetic-mean helper in
`src/util/math.ts`, already used by `MAD` and `Ichimoku`; `h.array` is
the raw buffer, so no array is allocated. Order is irrelevant to a
mean, so the raw buffer is preferable to `normalizedArray`, which
allocates. No new helper is introduced.

The seed loop runs once per indicator lifetime, replacing `n`
single-addition updates — the same `O(n)` total work as today, with no
per-bar cost after the seed.

## §2. Contract decisions the spec left open

- §2.1 **The unused state slot stays.** `SUM_FOR_INITIAL_EMA` /
  `SUM_FOR_FIRST_RMA` keep their enum entries (so `stateSize` stays 3)
  with a comment saying they are no longer read. Spec §4.2 forbids
  changing the layout; removing the enum member would shrink the
  `Float64Array` and break `restoreState` of a state exported by the
  current version. Old states restored into the fixed code are
  *corrected*, not broken: the window travels in the exported state
  too, so a restore mid-window re-seeds from the window.

  Verified across the two revisions (a `1.3.2` worktree exporting, this
  tree restoring) — something a single-revision unit test cannot do:
  - a state exported **after** the old seed was set continues
    value-for-value identically under the fix, so a consumer that
    persists indicator state sees **no discontinuity on upgrade**. A
    running average keeps its slightly-low value rather than lurching;
    only averages started after the upgrade are seeded correctly.
  - a state exported **mid-window**, whose slot 2 still holds the stale
    running total, ignores it and re-seeds from the window, matching an
    uninterrupted run on the fixed code exactly.
- §2.2 **A gap inside the first window returns `null`, not `NaN`**
  (spec §1.1.5). `null` is the warm-up signal the return type already
  carries; a `NaN` escapes into consumer arithmetic silently. Because
  `CURRENT` stays `NaN`, the seed branch is retried each bar and the
  first value arrives once `interval` clean inputs are in a row.
- §2.3 **A gap after the first value stays `NaN` for that bar** — the
  regular branch is untouched — and then the average restarts via the
  same retry. Not silently continuing from a stale value is the
  behaviour change; it follows from §2.2 rather than being chosen
  separately.
- §2.4 **JIT extraction tier: 0.** Both `calculate()` bodies are
  already pure arithmetic over in-memory state, with no I/O to
  separate. There is no smell to extract — only a wrong expression to
  replace. A higher tier here would be a drive-by rewrite of a
  hot-path class.

## §3. Blast Radius

1. **Other call sites.** `EMA` and `RMA` are used across the library by
   `ATR`, `MACD`, `DEMA`, `TEMA`, `ADX`/`DX`, `RSI`, Bollinger and
   Keltner with an EMA basis, `MAR`, the volume oscillator, the
   divergence indicator and the TA rating. All consume them through
   `next()`; none reads state slot 2. The change is confined to the two
   `calculate()` bodies — no signature, no export, no state shape.
2. **`core/` submodule.** This repo has none (`.gitmodules` absent).
3. **Owned/emitted contract.** The repo's own `CLAUDE.md` names the
   numeric output as the contract: "A change to indicator output
   (values, `IndicatorEnum`, warmup math) silently changes bot signals,
   backtests, and archived indicator results across every consumer.
   Treat the public API + numeric output as a contract; bump the
   version and coordinate consumers." This change moves values in the
   first bars after a start — deliberately, spec §4.3. So: minor
   version bump and a changelog entry saying so. Consumers
   (`main-app`, `main-app-sh`, `market-archive`, `backtester`) pin
   `@gainium/indicators` and pick it up on a deliberate bump, not
   automatically.
4. **Other tests on this path.** `test/placeholder.spec.ts` is the only
   existing test file; it must stay green. The full suite is the gate.
5. **Measured, not assumed.** 1 000 synthetic candles through 17
   indicators on this tree and on `origin/main`, compared bar by bar.
   Every difference is confined to a leading window and then goes to
   exactly zero — the seed-decay signature, no permanent drift:

   | indicator | bars differing | last differing bar | first-value diff |
   |---|---|---|---|
   | `EMA(9)` | 84 | 91 | 11.13 % |
   | `EMA(200)` | 801 | 999 | 0.48 % |
   | `RMA(14)` | 245 | 257 | 7.14 % |
   | `ATR(14)` | 243 | 255 | 6.08 % |
   | `MACD(12,26,9)` | 305 | 358 | see note |
   | `DEMA(20)` | 192 | 229 | 5.42 % |
   | `TEMA(20)` | 200 | 256 | 4.88 % |
   | `SuperTrend(3,10)` | 134 | 142 | 0.13 % |
   | `Keltner(20, ema, atr10)` | 178 | 196 | 4.97 % |
   | `VO(5,10)` | 39 | 47 | see note |
   | `MAR(EMA9, EMA21)` | 187 | 214 | 4.65 % |
   | `SMA(20)`, `WMA(20)`, `HMA(20)`, `CCI(20)` | **0** | — | 0 % |
   | `ADX(14)`, `RSI(14)` | **0** | — | 0 % |

   Note: `MACD` and `VO` are oscillators that cross zero, so a
   *relative* difference is meaningless near a crossing (it reads 140 %
   and 172 %); the bar counts are the meaningful figures for those two.

   `ADX` and `RSI` come out identical even though both are Wilder
   indicators, because they smooth with `WSMA`, which seeds itself from
   a real `SMA` instance (`src/WSMA/WSMA.ts`) rather than from a running
   total. This contradicts the report's affected list, which names both.
   The four unrelated controls being bit-identical is the evidence that
   nothing outside `EMA`/`RMA` moved.
